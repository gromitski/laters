# Laters v0.7.0 — reviewed CSV import

## Status

Released on 2026-08-26 after automated verification, privacy and dependency audits,
successful GitHub Pages deployment and published maintainer acceptance on macOS Chrome.

The lightweight `v0.7.0` tag resolves to exact verified release commit `d13a08b`. GitHub Pages
workflow `32956771733` passed before publication, and the GitHub release is published as the latest
release.

Package metadata is aligned to `0.7.0`. This release adds an explicit local, add-only CSV import
without changing existing articles, broadening Google Drive permissions or adding a Laters service.

## Included

- **Import CSV** beside **Download CSV** in the main application menu.
- Complete round-trip support for the version-1 Laters export and simpler named-column CSV files
  containing required `url` plus optional `title`, `created` and `tags` columns.
- Whole-file validation, a review summary and deliberate confirmation before any imported row is
  saved.
- A 10 MB and 1,000-article-row boundary with clear handling of existing URLs, repeated rows,
  additional columns and unsupported tags.
- One atomic IndexedDB transaction for accepted articles and ordinary pending Drive additions.
- Preserved saved times, bookmark state and deliberate-title state, with fresh private identifiers
  for every imported article.
- Successful completion that closes the menu, reveals and focuses the first imported article in its
  preserved saved-time position, and presents a conventional success tick.
- A package-derived version label in the main menu for support and update diagnosis.

## Data, privacy and compatibility

Import is entirely user initiated. The selected CSV is read locally after the user chooses it; the
file itself is never uploaded to Google Drive or another service.

Import accepts no Google credential, token, account or connection information; local article or
operation identifiers; pending or remote operation fields; deletion history; Drive file or
checkpoint metadata; or other private implementation bookkeeping. Invalid or cancelled imports add
neither articles nor pending operations.

The merge is add-only. Exact canonical URLs already present on the current device and repeated URLs
in the file are skipped without replacing titles, saved times, bookmark state or deliberate-title
state. New articles and their ordinary pending add operations commit atomically. A connected Drive
list is refreshed before duplicate review and processes those normal additions after commit; a
disconnected remembered connection produces a local-only warning.

Existing IndexedDB articles, Drive records and operation files remain compatible. There is no data
migration, backend, Laters account, analytics, automatic import, new Google permission, replace mode,
deletion mode or rollback mode.

## Known boundaries and deliberately deferred work

- Import preserves valid `created` values, so historically older articles remain below newer saved
  items rather than moving to the top.
- Import does not map arbitrary third-party column names, folders, archives, general tags, article
  content or attachments.
- Duplicate identity remains the exact canonical URL. Laters does not follow redirects or infer that
  different feed, tracking or rotating URLs represent the same article.
- Files exceeding 10 MB or 1,000 article rows are deliberately rejected rather than partially
  imported.
- Dark mode is the next intended product slice but is not defined or implemented by this release.
  Folders, archive, analytics and a Laters backend remain outside the roadmap.
