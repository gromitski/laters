# Laters v0.5.1 — automatic Drive housekeeping

## Status

Released on 2026-08-23 after automated verification, privacy and dependency audits, successful
GitHub Pages deployment and maintainer acceptance on updated Android and desktop installations.
This is a backward-compatible maintenance release built on `v0.5.0`.

Google Drive access remains a private experiment. The OAuth app is still in Google's **Testing**
state with only the maintainer admitted; this release does not authorise public OAuth access.

## Included

- Automatic housekeeping when 100 Google Drive operation files have accumulated, preventing the
  sync folder from growing indefinitely during ordinary personal use.
- A version-2 reading-list checkpoint containing the resolved article list and the exact operation
  identifiers it covers. Existing version-1 Drive snapshots remain readable.
- A deliberately staged cleanup: Laters writes the checkpoint first, waits for a later sync pass to
  adopt the settled result, and only then deletes the exact covered operation files.
- Safe recovery when Drive deletion is interrupted. The checkpoint remains authoritative, normal
  syncing continues and cleanup retries on a later check.
- Active-device checkpoint refresh before pending local work is uploaded. A pending operation already
  covered by the checkpoint is acknowledged without creating a duplicate Drive file.
- Repeated housekeeping. Once another 100 changes accumulate, the same bounded process runs again;
  the 100-change threshold is not a limit on the number of saved articles.

## Data, privacy and compatibility

Laters remains local-first and continues to work without Google Drive. The feature adds no backend,
account system, device registry, analytics, public storage or broader Google permission. Checkpoints
and operation files stay in the same private Drive application-data area covered by the existing
privacy policy.

The current article safety ceiling remains 10,000 items. If more than 100 operation files are present
when housekeeping starts, all valid covered operations in that settled checkpoint are processed; the
feature does not discard changes beyond the threshold.

## Verification and acceptance

- All 129 automated tests passed across 23 files, including the exact threshold, no cleanup below the
  threshold, version-1 compatibility, checkpoint validation, active-device adoption, delayed deletion
  and interrupted-cleanup retry.
- TypeScript checking, the Vite production build and service-worker generation passed.
- Repository and public-build privacy audits passed.
- Full and production-only dependency audits reported zero known vulnerabilities.
- The no-attribution guard and commit inspection passed with the configured privacy-safe identity.
- GitHub Pages workflow `32667577633` deployed the implementation successfully and the public origin
  served its matching verified production asset.
- After updating phone and desktop, the maintainer added an article on one device, watched it appear
  on the other, deleted it there and watched the deletion synchronize back successfully.

## Deliberately unchanged

- Visible syncing still occurs on open, foreground, online and 20-second checks; a closed or suspended
  PWA cannot promise background polling.
- Google OAuth remains in **Testing** and public access is still a separate product decision.
- The menu, status colours, article interactions and local-only behaviour are unchanged.
- Dropbox, OneDrive, arbitrary storage URLs, accounts, folders, archive, import/export, dark mode,
  reading-time estimation and automatic title enrichment remain outside this release.
