# Laters v0.5.0 — private Google Drive sync

## Status

Released on 2026-08-23 after automated verification, dependency and public-build security audits,
GitHub Pages deployment, browser verification and focused maintainer testing on Android and desktop.
This is a backward-compatible minor release built on `v0.4.2`.

Google Drive access remains a private experiment. The OAuth app is still in Google's **Testing**
state with only the maintainer admitted; this release does not make Google sign-in generally
available or authorise a move to public OAuth production.

## Included

- Optional Google Drive sync using only the narrow `drive.appdata` permission and hidden
  Laters-owned application files. Laters cannot browse or alter ordinary Drive files.
- A local operation journal for additions, duplicate captures, title edits, bookmark changes,
  deletions and Undo restores. Each visible change is saved atomically with its pending sync work.
- Immutable per-operation Drive files so simultaneous device uploads do not overwrite one another.
  Connected installations deterministically replay additions, updates, deletions and explicit
  restores over the existing base snapshot.
- Retained deletion records so an older installation cannot normally revive a deleted article.
  Re-adding a deleted URL intentionally creates a new article identity.
- Drive checks after opening, reconnecting, returning to the foreground or regaining connectivity,
  and every 20 seconds while Laters remains visible.
- Short-lived browser authorization recovery. Google's access token is retained in that browser
  only until its supplied expiry, with a safety margin; expired or rejected credentials are removed
  and local changes wait safely for **Reconnect Google Drive**.
- A permanent top-right application menu containing the unchanged Experimental sync card, local/
  Drive storage disclosure and public Privacy link.
- A three-state menu indicator: pale green after a successful Drive check, white while connecting,
  checking or sending, and pale red when disconnected, offline, expired or failed. Its accessible
  name communicates the same state without relying on colour.

## Data, conflicts and cleanup

Local IndexedDB remains fully usable without Google Drive and is still updated before any network
work. A failed upload never discards the local change. The existing `laters-reading-list.json` base
snapshot remains compatible with the earlier private snapshot proof, while new mutations are stored
as bounded immutable operation files.

Operations sort by occurrence time and unique operation identifier. Delete defeats an ordinary stale
update for the same article; only an explicit Undo restore can remove that deletion state. Competing
title or bookmark updates use the last deterministic replay result. Device clock differences may
affect competing edit order, but an ordinary edit cannot override a deletion.

Successfully uploaded local pending records are cleared. Remote operation and deletion files are
deliberately retained because deleting them without a device-acknowledgement boundary could revive
articles on a long-offline installation. Safe compaction remains future work.

## Interface and accessibility

The menu is reachable without traversing the article list and opens as an Ionic bottom drawer.
Backdrop selection, Escape, swipe-down and a visible **Close menu** control dismiss it, with focus
returned to the trigger. Reduced-motion preference removes drawer animation.

Desktop scrollbar space remains reserved while the modal locks page scrolling, so opening the drawer
does not move the centred application shell. Pointer-triggered focus restoration does not leave a
thick black outline on the circular controls; keyboard use retains a deliberate olive focus ring.

## Security, privacy and compatibility

There is still no Laters account, backend, refresh-token service, analytics system or shared Laters
database. The OAuth client identifier is public by design; no Google client secret is used or
committed. Google's identity script is requested only after deliberate connection activation.

The public privacy policy explains optional Drive storage and provides `hello@dustyb.in` as the
public support contact. Repository and public-build audits protect against credentials, private
paths, unintended email addresses, source maps and other non-public material entering Git history or
the deployed artifact.

Existing local-only installations and saved articles remain compatible. This release upgrades the
IndexedDB schema to retain pending operations and known remote operation identifiers, without
requiring Drive connection or replacing the visible local list after a failed/invalid remote read.

## Verification and acceptance

- All 122 automated tests passed across 23 files, including atomic operation journalling,
  deterministic replay, immutable Drive uploads, token expiry, serialized sync checks, menu state,
  pointer/keyboard focus treatment and the established interaction contracts.
- TypeScript checking, the Vite production build and service-worker generation passed.
- The repository privacy audit and public-build audit passed; the verified public build contains 19
  files and no credential, private-path, source-map or unintended static third-party-resource finding.
- Full and production-only dependency audits reported zero known vulnerabilities.
- The no-attribution guard and commit inspection passed with the configured privacy-safe identity.
- GitHub Pages deployments for live sync, the application menu, its state indicator and the drawer
  stability correction passed. Production served the exact verified JavaScript and CSS assets.
- The maintainer completed the narrow Google consent flow in Chrome and Android, uploaded the initial
  17-article snapshot, loaded it into another installation, confirmed a bookmark round trip and later
  confirmed phone and desktop live-sync connections were working.
- Desktop maintainer acceptance confirmed the menu placement, state simplicity, stable centred page
  and corrected pointer-focus presentation.

## Known boundaries and deliberately deferred work

- The complete representative phone/desktop add, delete, Undo and expiry-boundary acceptance
  sequence remains to be recorded. This release therefore does not claim fully closed multi-device
  physical acceptance.
- Android drawer reachability, internal scrolling and swipe-down dismissal remain targeted physical
  checks; existing automated and desktop acceptance does not substitute for them.
- Laters cannot promise polling while the PWA is closed or suspended. Indefinite unattended
  authorization would require backend-held refresh credentials, which remain out of scope.
- Safe compaction of remote operations and tombstones remains deferred. Current retention is suitable
  for private personal testing, not an accepted public-scale storage policy.
- Dropbox, OneDrive, arbitrary storage URLs, public OAuth access, accounts, folders, archive,
  import/export, dark mode, reading-time estimation and automatic title enrichment remain out of
  scope.
