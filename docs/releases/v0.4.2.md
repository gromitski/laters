# Laters v0.4.2 — easier capture and desktop access

## Status

Released on 2026-08-23 after automated verification, dependency and public-build security audits,
GitHub Pages deployment, browser verification and maintainer acceptance on mobile and desktop. This
is a backward-compatible feature release built on `v0.3.0`. The `v0.4.0` and `v0.4.1` numbers were
production candidates within this release line, not separate tags or GitHub releases.

## Included

- **Share this article** in the long-press/context action sheet. It invokes the platform's generic
  share chooser with exactly the saved URL—no title or added text—and has no receiver-specific
  integration.
- The current white, ink and lime application shell on the normal desktop browser page, with a
  contextual **Install** action beside the wordmark when the browser reports that installation is
  available.
- A persistent **Paste a link** row. It reads clipboard text only after deliberate activation and
  falls back to an inline labelled URL field with **Add** when direct clipboard capture is unavailable
  or unsuitable.
- HTTPS defaulting for bare web addresses and one central URL-validation boundary for Share Target,
  clipboard and manual-entry capture paths.
- **Edit title** immediately after **Read now** in the action sheet. It changes only the remembered
  local title; the URL, saved time, queue position and bookmark state remain locked.
- Deliberate title edits survive reopening and exact-URL re-capture while the normal duplicate
  refresh still updates the saved time and moves the item to the top.
- A visible circular **More actions** control beside Delete on desktop mouse/trackpad layouts,
  reusing the existing action sheet while retaining right-click and `Shift+F10`.
- A modest responsive desktop shell that grows fluidly from the established 34rem column to a 42rem
  maximum without changing the mobile presentation or becoming a separate desktop design.

## Accessibility and interaction safety

The title remains a semantic original-URL link, and visible Bookmark and Delete controls remain
available. Touch long press, both swipe directions, whole-row opening, right-click and keyboard menu
access continue to route through the same underlying actions. The new desktop menu button has an
article-specific accessible name, a visible focus treatment and focus restoration after dismissal;
its name follows a deliberate title edit. It is absent from the mobile layout rather than becoming
an extra hidden mobile tab stop.

The title editor is a labelled native modal with selected current text, Cancel and Save controls,
empty-title validation, storage-failure guidance, Escape and backdrop dismissal, and polite success
announcement. Sharing cancellation returns safely to Laters.

## Security, privacy and data compatibility

Every new capture path accepts only normalised HTTP or HTTPS article URLs. Unsafe schemes,
credential-bearing URLs, malformed escapes, control characters, embedded whitespace and excessive
length are rejected. Bare addresses default to HTTPS. Input is stored and rendered through existing
typed and text-only boundaries; Laters does not fetch pasted pages or inject saved input as markup.

Clipboard access is user initiated. Saved articles and edited titles remain in the browser's
IndexedDB database. This release adds no account, backend, analytics, API key, sync service or
committed user data. It adds one optional backward-compatible `titleEdited` marker without changing
the database version, so existing `v0.1.0`–`v0.3.0` records remain valid.

The workflow deploys only the audited generated `dist/` directory. Its repository token is read-only
except for the isolated Pages deployment job, which receives only Pages and identity-token write
permissions. Third-party workflow actions are pinned to exact commits.

## Verification and acceptance

- All 96 automated tests passed across 17 files, including the URL-only share payload, URL
  validation, title persistence and exact-URL re-capture contracts.
- TypeScript checking, the Vite production build and service-worker generation passed.
- The public-build privacy audit passed across 16 generated files with no secret, local-path,
  source-map or unintended static third-party-resource finding.
- Full and production-only dependency audits both reported zero known vulnerabilities.
- The no-attribution guard and commit inspection passed with the configured privacy-safe identity.
- GitHub Pages runs `32637456916` and `32637560143` passed; production served the matching verified
  JavaScript and CSS assets.
- Browser verification covered the 320px mobile presentation, progressive desktop widths, the 1280px
  production presentation, retained IndexedDB data, More-actions menu opening, accessible naming,
  focus restoration and an error-free console.
- Physical Android sharing confirmed the generic chooser, URL-only NotebookLM import and safe
  cancellation. The maintainer subsequently confirmed the mobile paste and title-edit flows work as
  intended, then accepted the final desktop width and More-actions placement. No newer Android
  version was recorded, so the established Chrome for Android support claim is not broadened.

## Deliberately deferred

Cross-device sync and identity, automatic remote title enrichment, approximate reading time,
alternative ordering, dark mode, export/import, folders, archive and article images remain
exploratory. This release adds no bulk intake, browser extension, receiver-specific sharing,
full-width desktop dashboard or general desktop makeover.
